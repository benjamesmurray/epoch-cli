# Epoch CLI - E2E Variance Testing Harness

This directory contains a robust, TypeScript-based testing harness designed to evaluate the autonomous coding capabilities of the `epochcli` agent. It replaces legacy bash scripts with a fully managed, containerized execution environment that tracks agent success rates, failure modes, and tool usage across multiple iterations.

## Core Features

- **Dockerized Isolation (`--network none`)**: Agents execute inside ephemeral Docker containers (`epochcli-eval-env`) with zero network access. This guarantees the model cannot "cheat" by fetching external snippets and ensures a 100% pristine filesystem for every test run.
- **Local Source Testing**: The harness mounts your local `/home/benmurray/Projects/cli` repository as read-only (`:ro`) into the container. This means you can test your local, uncommitted CLI changes instantly without rebuilding the Docker image.
- **Offline MCP Servers**: The Docker image comes pre-installed with the required local MCP servers (`spec`, `project-map-cli`, `ground-truth-cli`). The harness dynamically generates a `.gemini/settings.json` for each run to point the agent to these offline binaries.
- **Real-Time Observability & Loop Detection**: The harness streams the agent's `stdout`/`stderr` in real-time to provide live terminal feedback. You will see a "pulse" of every tool invocation (e.g., `🛠️ Tool Invoked: sc_init`) and every middleware JSON repair. If the agent repeats identical tool calls, the engine emits an early warning before instantly killing the container if the loop threshold is breached. Full raw logs are always saved alongside the code for deep inspection.
- **Automated Code Evaluation**: After the agent completes a run, the harness automatically executes `bun test` against the agent's generated workspace to verify the code actually works. If the agent generates a `tsconfig.json`, the evaluator will also run a strict type check (`bunx tsc --noEmit`) before running functional tests. Both must pass.
- **Evidence Preservation**: All iterations of a single test suite are grouped into a timestamped directory (e.g., `suite_YYYY-MM-DD-HH-MM-SS`) inside the isolated `/home/benmurray/Projects/epochclievaluations` workspace. The harness captures the raw code generated by the agent, as well as a full `run.log` of the `stdout/stderr` streams, allowing for deep forensic analysis later.
- **Variance Reporting**: Aggregates the results of all iterations into a detailed Markdown report (`variance_report.md`) saved directly into the timestamped suite folder, tracking success rates, JSON repairs, and specific failure modes (e.g., `Failed_Tests`, `Killed_Loop`, `Killed_Timeout`).

## Quick Start

### 1. Build the Evaluation Image
Before running tests, you must build the base Docker image. This image contains Bun, Node, Python, and the globally installed MCP servers.

```bash
cd e2e_testing/harness
./build-image.sh
```
*(You only need to re-run this if you want to update the globally installed NPM versions of the MCP servers or change the baseline context files like `.assistant_rules.toon`)*

### 2. Configure Your Tests
Define your test scenarios in `e2e_testing/harness/test_config.json`. 

Example configuration:
```json
[
  {
    "id": "eventbus-v2",
    "iterations": 5,
    "timeoutMs": 300000,
    "prompt": "Use the Spec CLI to initialize a new project called '$RUN_ID' in one-shot mode...",
    "expectedTools": ["sc_init", "sc_todo_start", "sc_todo_complete", "sc_plan"],
    "runTargetDir": ".epochcli/tool/$RUN_ID",
    "docker": {
      "imageName": "epochcli-eval-env:latest",
      "network": "none",
      "memoryLimit": "4g"
    }
  }
]
```

### 3. Run the Suite
Execute the harness using Bun. You can override the number of iterations defined in the JSON file by passing the `--iterations` flag.

```bash
cd e2e_testing/harness
bun run src/index.ts --iterations 10
```

The harness will output live progress to the console. Once all iterations are complete, it will provide the path to your timestamped `suite_...` directory containing the `variance_report.md` and all preserved evidence (code and logs).

## Architecture

- **Workspace Mounts**: To prevent polluting the main repository, all temporary agent workspaces are created in `/home/benmurray/Projects/epochclievaluations/suite_$TIMESTAMP/$RUN_ID`. This specific run directory is mounted into the Docker container at `/workspace`.
- **HeuristicsEngine**: Parses the live log stream looking for explicit MCP tool invocations and tracks the `json_repaired` metric. It throws a `LoopException` if it detects identical tool calls repeating consecutively beyond the threshold.
- **TestEvaluator**: Spawns a secondary, ephemeral Docker container using the same image to run `bunx tsc --noEmit` and `bun test` inside the generated code folder, ensuring exact environmental parity.
- **Permissions Management**: The `AgentRunner` automatically appends a `chmod -R 777 /workspace` command to the end of the agent's execution. This ensures that files created by the `root` user inside Docker can be cleanly deleted by the host machine if needed.
