# Epoch CLI - E2E Variance Testing Harness

This directory contains a robust, TypeScript-based testing harness designed to evaluate the autonomous coding capabilities of the `epochcli` agent. It replaces legacy bash scripts with a fully managed, containerized execution environment that tracks agent success rates, failure modes, epoch transitions, and tool usage across multiple iterations.

## Core Features

- **Dockerized Isolation (`--network bridge`)**: Agents execute inside ephemeral Docker containers (`epochcli-eval-env`). This guarantees a pristine filesystem for every test run while allowing controlled network access for dependency installation.
- **Local Source Testing**: The harness mounts your local `/home/benmurray/Projects/cli` repository as read-only (`:ro`) into the container. This means you can test your local, uncommitted CLI changes instantly without rebuilding the Docker image.
- **Host-Driven Black-Box Evaluation (New Architecture)**: Instead of relying on the agent to grade its own homework by writing unit tests, the harness supports true black-box E2E testing. It can boot the agent's generated application in a detached container with dynamic port mapping, poll for health, and execute host-side test scripts (e.g., REST/WebSocket assertions) against the live container.
- **Epoch Transition Resilience**: The harness is designed to test the CLI's "Infinite Agent" capabilities. It natively tracks and handles automatic **Epoch Transitions** when the agent hits context limits, ensuring long-running projects can be evaluated seamlessly.
- **Real-Time Observability & Loop Detection**: The harness streams the agent's telemetry in real-time to provide live terminal feedback. You will see a "pulse" of every tool invocation, epoch transitions, and JSON repairs. The engine includes immediate loop protection mechanisms (Stall Scoring) to abort non-productive runs.
- **Evidence Preservation**: All iterations of a single test suite are grouped into a timestamped directory (e.g., `suite_YYYY-MM-DD-HH-MM-SS`) inside `e2e_testing/results`. The harness captures the raw code generated by the agent, full `run.log` stream, initial payloads, and prompt history for deep forensic analysis.
- **Variance Reporting**: Aggregates the results of all iterations into a detailed Markdown report (`variance_report.md`), tracking success rates, duration, and specific failure classifications (e.g., `Failed_Tests`, `Killed_Loop`, `Killed_Timeout`).

## Quick Start

### 1. Build the Evaluation Image
Before running tests, you must build the base Docker image. This image contains Bun, Node, Python, and the globally installed MCP servers.

```bash
cd e2e_testing/harness
./build-image.sh
```

### 2. Configure Your Tests
Define your test scenarios in a JSON file (e.g., `iot_controller_config.json`). 

Example configuration with Black-Box Evaluation:
```json
[
  {
    "id": "iot-controller-full-stack",
    "iterations": 10,
    "timeoutMs": 3600000,
    "prompt": "Build a Smart Home IoT Controller. You MUST expose a web server on 0.0.0.0:8080 and provide a start.sh script.",
    "expectedTools": ["sc_init", "sc_plan", "write_file"],
    "runTargetDir": ".",
    "evaluation": {
      "type": "host_blackbox",
      "startupCommand": "bash start.sh",
      "port": 8080,
      "testScript": "evaluators/iot_eval.test.ts"
    },
    "docker": {
      "imageName": "epochcli-eval-env:latest",
      "network": "bridge",
      "memoryLimit": "4g",
      "model": "local-main/qwen-35b"
    }
  }
]
```

### 3. Run the Suite
Execute the harness using Bun. You can override the number of iterations defined in the JSON file by passing the `--iterations` flag.

```bash
cd e2e_testing/harness
bun run src/index.ts --config iot_controller_config.json --iterations 1 --yolo
```

The harness will output live progress to the console. Once all iterations are complete, it will provide the path to your timestamped `suite_...` directory containing the `variance_report.md` and all preserved evidence.

## Architecture

- **Workspace Mounts**: To prevent polluting the main repository, all temporary agent workspaces are created in `e2e_testing/results/suite_$TIMESTAMP/$RUN_ID`. This specific run directory is mounted into the Docker container at `/workspace`.
- **Telemetry Engine**: Parses the live `.jsonl` telemetry stream looking for explicit MCP tool invocations, epoch transitions, and tracks performance metrics.
- **TestEvaluator (Dual Mode)**: 
  - **Black-Box Mode**: If an `evaluation` block is present, it boots the generated code in a detached Docker container, maps ephemeral host ports, and executes the `testScript` from the host machine against the dynamic `TARGET_URL`.
  - **Legacy Mode**: If no evaluation block is present, it falls back to inspecting the generated codebase and running embedded test commands (e.g., `bun test`, `pytest`) directly inside an ephemeral container.
- **Permissions Management**: The `AgentRunner` automatically executes cleanup commands to ensure that files created by the `root` user inside Docker can be cleanly manipulated or deleted by the host machine.
